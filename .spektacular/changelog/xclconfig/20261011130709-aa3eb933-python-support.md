# The xcl package for Python: the xcl engine with a synchronous and an asyncio API

XCL for Python is a package, `pip install xcl-lang`, imported as `xcl`, that bundles the xcl engine for its platform and needs no Go toolchain or C compiler. A Python program describes entity types as dataclasses, registers Python functions, uses Go-compiled plugins from a path, a directory or the GitHub registry, passes variables, keeps state in a directory or in its own store, receives events, and validates, diffs, applies, loads and destroys configuration with the same results a Go program gets, through `xcl.Config` or, for asyncio services, `xcl.aio.Config`, whose operations never block the event loop and can be cancelled.

> Derived from project xclconfig (spektacular), spec/plan 20261011130709-aa3eb933-python-support. See the project-level record for the full feature.

## What changed in this repo

- The package itself: `pyproject.toml` (hatchling, CPython 3.10+, `protobuf` and `cffi`, wheels tagged `py3-none-<platform>` through `hatch_build.py`), a `Makefile` to generate the messages, build the engine and the fixture plugins from an xcl checkout and run the tests, the Apache-2.0 licence and ignore rules.
- The transport (`xcl/_transport`): lazy loading of libxcl with cffi in ABI mode or ctypes, the GIL released during calls, every response freed, the ABI check, and the fork guard raising `ForkedProcessError`.
- The client and errors (`xcl/_client.py`, `xcl/_errors.py`): the descriptor-built client, the engine version check, and one exception class per engine error code under `xcl.Error`, with `ConfigError.problems`.
- Entity types (`xcl/_types.py`, `xcl/_entity.py`, `xcl/_schema.py`): `@xcl.entity`, `Resource`, `Meta`, `Entity`, `Sensitive`, `Computed`, `field`, `UNKNOWN`, schema derivation, function signature derivation and hydration.
- The synchronous API (`xcl/config.py`, `xcl/registry.py`, `xcl/mask.py`, `xcl/events.py`, `xcl/diff.py`, `xcl/_poll.py`, `xcl/_functions.py`): every option, operation and lookup, registries, masks, events, diffs, the poll engine and Python functions.
- The asyncio API (`xcl/aio.py`).
- Tests: unit tests against a fake transport, integration tests against the engine for every acceptance criterion, Docker plugin tests with a fake GitHub API for tampered and untrusted releases, the Go–Python parity suite, and asyncio tests.
- CI and release workflows (`.github/workflows/ci.yml`, `release.yml`), the README, `PARITY.md`, and docstrings on every public name with a test that checks them.

## Why

Python developers could not use XCL. This package gives them the same engine Go programs use rather than a reimplementation, so the results match Go's exactly and the same plugins work; the synchronous API suits scripts and command-line tools, and the asyncio API keeps a service answering requests during a long apply.
